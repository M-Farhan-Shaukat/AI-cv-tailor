Every job description is a list of search terms in disguise. Recruiters use the same words when they filter candidates in their applicant tracking system, so learning to pick them out is the most useful CV skill you can build. Here is a simple method that works for any role.

## Step 1: Read the requirements section first

Skip the company introduction and benefits. Go straight to sections titled *Requirements*, *Qualifications*, *What you'll need* or *About you*. These are the terms most likely to be used as filters.

As you read, note anything that is a concrete, searchable thing:

- **Hard skills and tools:** Python, Excel, Salesforce, AutoCAD, SQL
- **Methods and practices:** Agile, code review, financial modelling, A/B testing
- **Qualifications:** "Bachelor's degree in Computer Science", "ACCA", "PMP"
- **The job title itself:** "Data Analyst", "Senior Backend Engineer"

## Step 2: Separate "required" from "nice to have"

Words like *must*, *required* and *essential*, or anything repeated several times, are your priority. Phrases such as *a plus*, *preferred* or *bonus* are worth including if you have them, but they matter less. Most ranking systems weigh required skills more heavily.

## Step 3: Note the exact spelling

ATS keyword matching is literal more often than you would expect. If the job says "Node.js", write "Node.js", not "NodeJS". If it says "CI/CD", use that form. When a term has a common abbreviation, write both once: "Continuous Integration/Continuous Deployment (CI/CD)".

## Step 4: Ignore the noise

Not everything in a job description is a keyword. Leave out:

- generic verbs ("contribute", "support", "work with")
- personality filler ("passionate", "rockstar", "self-starter")
- years of experience ("3+ years"); these are screening questions, not search terms
- company culture and benefits text

Keep a short list of soft skills only if they are clearly emphasised, for example "communication" or "stakeholder management".

## Step 5: Map each keyword to evidence

Now go through your list and, for every keyword, find where your CV proves it. You will end up with three groups:

1. **Already there, same wording.** Good: make sure they also appear in your experience, not just a skills list.
2. **There, but in different words.** Reword to match the job, as long as it stays accurate.
3. **Not there.** If you genuinely have the skill, add it with a real example. If you do not, leave it out.

## A quick example

A job ad says: *"You will build and maintain REST APIs in Laravel, write unit tests, and take part in code reviews. Experience with Docker is a plus."*

Your keyword list: **REST APIs, Laravel, unit testing, code review** (required) and **Docker** (preferred). If your CV says "developed web services using PHP frameworks", rewrite it as "Built and maintained REST APIs in Laravel", which is the same experience in the employer's words.
